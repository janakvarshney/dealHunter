# DealHunter — Data Sources Research

> **Status:** Research phase | **Last Updated:** 2026-10-05

This document records research into each potential data source: legal constraints, API availability, terms of service, and our approach for each.

---

## ⚠️ IMPORTANT: Legal & Ethical Notice

Before integrating any marketplace, we must verify:
1. **Terms of Service** — Does the platform prohibit scraping?
2. **robots.txt** — Are product pages disallowed?
3. **API availability** — Is there an official API we should use instead?
4. **Affiliate program** — Can we use affiliate feeds legitimately?
5. **Rate limits** — What are the crawl rate restrictions?

**We will NOT implement unauthorized scraping simply because it is technically possible.**

If a platform prohibits scraping and has no open API, we use a **mock connector** during development and document how to add real integration when legal access is obtained.

## Amazon India

**API:** Amazon Product Advertising API 5.0 (PA-API 5.0)  
**Documentation:** https://webservices.amazon.com/paapi5/documentation/  
**Requirements:**
- Must be an Amazon Associates member
- Minimum sales requirement: 3 qualifying sales within 180 days of API key issuance
- Rate limit: 1 request/second (burst: up to 10 TPS)
- Data: Title, price, availability, product images, reviews
- Legal: Data may only be used to link to Amazon; display rules apply

**MVP Approach:** Mock connector with realistic Amazon-style product data  
**Phase 2:** Register for Amazon Associates IN, obtain PA-API credentials

---

## Flipkart

**API:** Flipkart Affiliate API  
**Documentation:** https://affiliate.flipkart.com/introduction  
**Requirements:**
- Flipkart Affiliate account required
- Product feed available as XML/JSON
- Rate limits apply
- Data: Product name, price, MRP, discount, URL, image

**MVP Approach:** Mock connector  
**Phase 2:** Register for Flipkart Affiliate program

---

## Croma

**API:** None publicly available  
**Web:** https://www.croma.com  
**robots.txt:** Restricts automated crawlers  
**Approach:** Mock connector only. No real integration planned until official API/partnership is available.

## Mock Data Strategy (MVP)

All MVP connectors use **realistic mock data** generated by `scripts/generate-mock-data.ts`.

### Mock Data Principles
1. **Realistic product titles** matching real naming conventions per platform
2. **Price variation** across sources (±5–15%)
3. **Realistic discounts** (0–25%)
4. **Realistic seller ratings** (3.5–4.9 for major sellers)
5. **Realistic delivery estimates** (1–7 days depending on location tier)
6. **90 days of historical price data** with realistic variations

### Mock Data Structure
Each connector's mock module contains:
- A static JSON dataset of realistic products
- A search function that filters by query
- Price variation logic to simulate different prices per source

## ProductOffer Schema (Common Output)

All connectors must output this schema regardless of source:

```typescript
interface ProductOffer {
  // Source identification
  source: 'amazon_in' | 'flipkart' | 'croma' | 'reliance' | 'myntra' | 'meesho';
  externalProductId: string;           // Platform's own product ID
  
  // Product identity
  title: string;                        // Raw title from source
  brand: string;                        // Normalized brand name
  model: string;                        // Normalized model name
  category: string;
  variant: {
    storage?: string;                   // e.g., "256GB"
    ram?: string;                       // e.g., "8GB"
    color?: string;                     // e.g., "Midnight Black"
    size?: string;                      // For appliances
  };
  
  // Pricing
  listedPrice: number;                  // Original MRP (INR)
  discountedPrice: number;              // Current selling price (INR)
  discount: number;                     // Percentage discount
  shippingCost: number;                 // 0 if free shipping
  taxEstimate?: number;                 // If available
  
  // Availability
  availability: 'in_stock' | 'out_of_stock' | 'limited_stock' | 'unknown';
  
  // Seller
  seller: {
    name: string;
    rating: number;                     // 1–5
    reviewCount: number;
  };
  
  // Product ratings
  productRating: number;                // 1–5
  reviewCount: number;
  
  // Delivery
  deliveryEstimateDays: number;
  isFreeDelivery: boolean;
  
  // Return policy
  returnPolicyDays: number;             // 0 if no returns
  
  // Links
  productUrl: string;
  imageUrls: string[];
  
  // Metadata
  fetchedAt: Date;
  identifiers?: {
    gtin?: string;
    ean?: string;
    upc?: string;
    mpn?: string;
    isbn?: string;
  };
}
```

## Adding a New Source (Future)

To add a new marketplace connector:

1. Create `backend/src/connectors/{source}/`
2. Implement `BaseConnector` interface
3. Output `ProductOffer[]` from `search()` method
4. Register in `ConnectorRegistry`
5. Add source to `SourceName` enum
6. Update this document with legal research

See [docs/connectors.md](connectors.md) for the full connector developer guide.
